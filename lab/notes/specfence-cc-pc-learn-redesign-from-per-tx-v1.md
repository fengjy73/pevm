# 从每笔界差重做 CC / PC / Learn

**日期:** 2026-09-22
**依据:** [`specfence-per-tx-vs-parallel-bound-v1.md`](specfence-per-tx-vs-parallel-bound-v1.md)，JSON `lab/results/per-tx-vs-bound/`。引擎 `95b635d`。
**性质:** 只设计。本轮不落地。Soft=0。不恢复 `next_task*`，不用 OCC pick 把挂住的块纸过去。

界差已经说明亏在哪里。可跑宽度不是亏。`W_lvl` 是 154–1120，复用 `runnable_width_mean` 是 68 / 71 / 525 / 70，请求核数是 8。理想 makespan 等于关键路径长度，因为链长于 `Σwork/C`。SF 复用墙是这条界的 7.5 / 6.8 / 16.4 / 93 倍。`(SF−LB)` 里 SpecFence 独有的一段（`SF−OCC`）占 74% / 74% / 60% / 46%；剩下的是 OCC 也付的并行开销。`3356896` 的 LB 低于运行时地板，那 46% 以外的「共有」不要读成 DAG 太窄。

---

## 0. 界差要求协议做什么

一笔交易相对理想调度的 slack，只允许来自两件事：它的真前驱还没完成，或者 8 个核当时都在跑更长的关键路径尾巴。除此以外的等待、重执行、重选，都是协议自己加上的非 DAG 约束。

因此下一版只有一条规则，没有 P0/P1/P2 分期：

- **Detect** 只认最近一个尚未提交的 RAW/WAW 前驱（或真实 nonce 前驱）。那个前驱一提交，门就拆。不链第二跳。peer 不在这条边上，就不许等。
- **Avoid** 没有未完成的 DAG 前驱就用 Opt。有，就只等那一个还活着的前驱。
- **Resolve** 读到的值真的变了，就重放一次。重放不留下一条前驱已经提交之后还活着的门。lazy 余额差不走 FullReplay。
- **Learn** 的合法输出只有下一次尝试的臂：Opt，或者「等这个还活着的前驱」。不能改变这个臂的信号不记录。不在最终读写 DAG 上的边不种植。
- **PC** 的优先级是到汇点的最长剩余时间。独立交易用来填其余的核。没有活着的 DAG 前驱的交易不重选。`release_owner` 留着。产品路径继续禁止 `force_push` 一个 `ST_RUNNING`。

## 1. P1–P5 相对这些笔错在哪

P1–P5 已经在 `95b635d` 上。它们没有拿掉非 DAG 等待，也没有拿掉关键路径的重执行。

**P1（值稳定 rebind，然后对已执行或正在执行的非 lazy EffectiveWAW 做 OrderedReplay）。** 复用上 partial rebind 仍是 0，E3 是 0 或 1。关键路径照样重执行：39/43、38/41、10/13、16/17。OrderedReplay 次数是 112 / 79 / 159 / 20，和 FullReplay 叠在同一条理想只跑一遍的链上。两块 C 的额外工作（12.1 ms、19.5 ms）大于整块 `Σwork`。把 OrderedReplay 收成「只在 `is_executing`」曾经量过，`19469097` 更差（pick/笔约 13，洞约 38 ms）。那个收法不要再当修复。界要求的是：前驱还活着时可以有序重放一次；前驱提交之后门必须死。`19469097` tx 316 在关键路径上，peer 315 是真前驱，停车时 315 已经完成，陈旧门仍有 24.86 ms 核时间。这就是一条活过提交的门。

**P2（风暴排队一条 IntraPatch，不 sticky-Opt；Win 应用后粘住；`n≤176` 不做 `promote_short_edge`）。** 复用四块 `chosen_strategy` 全是 Opt，`explore_n=0`。E5 贴着 E2 贴着 FullReplay（144/144、135/137、113/114、18/18）。`mid_promote` 是 7 / 25 / 6 / 0，`3356896` 还有 `mid_promote_veto=14`。计数在动，关键路径下一次尝试的可见性没有变成「等活前驱」。风暴被记下来了，臂没换。这是没用上的 Learn。与此同时，tx 335 和 tx 429 的门根本不在 DAG 上，那种 Learn 不该存在。

**P3（溢出链只种一跳，不延长活着的 tip）。** 洞还在：复用 `gate_stall_ns` 是 11.0 / 14.6 / 15.1 / 1.39 ms，三块大块的洞仍是数倍于 LB。一跳上限没有去掉假边。`19469097` tx 288 等 284（22.5 ms，不是它的严格前驱，也不是 lazy 边）。`15274915` tx 1169 等 1160（14.4 ms，lazy 命中 0）。`19860366` tx 412 / 413 的假边核时间各约 29 ms，413 在关键路径上。

**P4（失败的 owner 用 `release_owner`，不 `force_push` `ST_RUNNING`）。** 产品路径上的偷跑停了，Blocking 重选没有停。`19469097` tx 335：preds 0，lazy preds 0，`exec=156`，`blocked=155`，`max_inc=3`，`n_full=0`，makespan。`19860366` tx 429：同样 preds 0 / lazy 0，`exec=155`，`blocked=154`，`max_inc=4`，冷启动已经 139。`19860366` tx 329：有 1 个真前驱，`exec=235`，`max_inc=2`，`blocked=233`，vis 几乎全是 Opt。incarnation 没有跟着空转涨，所以这不是 abort 重执行，是门没拆、人被反复挑起来。禁止 `force_push` 是对的，它不解决这个。

**P5（薄块丢掉 idle-edge flush；lazy 高读者重校验留着）。** flush 这一刀和界一致：`3356896` 的 `W_lvl=154`，宽均值已经 70。剩下的 SF−OCC 约 1.29 ms，是路径头晚 1.25 ms 启动，加上 tx 67→171 每跳重放，不是 flush。跳过 lazy 重校验曾经让 `3356896` `seq!=par`（收据相同，一处账户余额不同）。那一刀保持不落地。

## 2. Learn：没用的，和不该存在的

没用的，是不能在下一次 incarnation 之前改变臂的信号。这四块上复用臂始终是 Opt，所以下面这些输出目前都是空转：

- E1 Commit 计数（503 / 582 / 1429 / 199）不选臂。
- E4（`refuse_fill` 之后跑了独立交易）不选臂。
- E6 lazy `force_opt`（0 / 5 / 2 / 1）不选臂。
- `explore_n=0` 的探索预算、sticky Opt、bandit 的 ĉ。策略名在冷启动上可以是 `Win_2` / `Win_1`（`19860366` 冷、`3356896` 冷），复用仍回到 Opt。Win 没有变成路径上的下一次可见性。
- `mid_promote` 排队了 IntraPatch，应用之后 `chosen_strategy` 仍是 Opt。排队本身不是臂。

不该存在的，是种植一条最终读写 DAG 上没有的等待：

- `19469097` tx 335 等 329/331/334。严格前驱 0，lazy 前驱 0。这条边不是被结构 DAG 丢掉的余额边。冷启动 exec 5，复用 exec 156，`began_from_prior`。prior 把一条非 DAG 门带进了下一块执行。
- `19860366` tx 429 等 421/427/428。同样两种前驱都是 0。冷启动就已经空转，不依赖 prior。
- `19469097` tx 288 等 284，`15274915` tx 1169 等 1160，`3356896` tx 171 等 141、tx 138 等 132。peer 都不是那一笔的严格前驱。

唯一对得上「丢掉的 lazy 边」的例子是 `3356896` tx 9：preds 0、lazy preds 1、peer 8。lazy 余额不是 Detect 的边。tx 335 / 429 连这个借口都没有。

E5 现在和 FullReplay 同数。它要么在本块剩余时间里把该笔的臂改成「等这个还活着的前驱」，要么不要记。记下来又 sticky 回 Opt，等于没有 Learn。

## 3. PC：不是没填满 W，是没先跑关键路径

`level_width` 和 `runnable_width_mean` 都远大于 8。独立交易理想起点是 0，干净反链（一次执行、没有门）的启动中位却是 5.74 / 3.28 / 4.09 / 0.70 ms。`corr(tx_index, first_start)` 是 −0.97 到 −0.99：高下标先跑。

这四块的关键路径都是下标递增的。倒序调度等于把路径头放到反链后面：

| block | 路径头 | 头的 SF 启动 | 头的 exec | 路径尾 | 尾的 SF 启动 | 尾的理想完成 | 尾的 SF 完成 |
|------:|-------:|-------------:|----------:|-------:|-------------:|-------------:|-------------:|
| 19469097 | 0 | 9.09 | 1 | 322 | 0.44 | 4.38 | 28.47 |
| 19860366 | 0 | 9.44 | 1 | 418 | 0.34 | 5.08 | 31.63 |
| 15274915 | 0 | 9.68 | 1 | 102 | 7.68 | 1.19 | 11.84 |
| 3356896 | 4 | 1.25 | 1 | 171 | 0.10 | 0.031 | 1.97 |

头自己没有重执行。尾在头启动之前就投机跑了，然后整段 slack 堆在尾和尾后面的非关键笔上（335、429、1219）。`15274915` 的额外工作只有 2.39 ms，墙仍是 LB 的 16 倍，因为 1111 笔干净反链被排到 4 ms 以后，而 13 笔关键路径的头在 9.7 ms 才开始。

PC 要改的是优先级，不是再扩宽度，也不是再种门：

- 优先级 = 到汇点的最长剩余时间。在这些块上就是低下标、长尾巴先跑。独立交易是填充。
- 一笔没有活着的 DAG 前驱，就不许再 pick。这直接打掉 tx 335 和 tx 429（前驱集合是空的，却被 pick 150 次以上），也打掉 tx 329 在前驱完成后的重选（`max_inc` 只有 2，说明值没有在变，变的是调度）。
- 前驱还活着时，停在门上，直到那个前驱提交。不要用 Opt 把同一笔再送进执行（tx 329 的 vis 是 235/0/0）。
- `release_owner` 保持。产品路径继续不 `force_push` `ST_RUNNING`。

## 4. Resolve：关键路径上多出来的工作

理想调度里关键路径上的每一笔只执行一次，工作量就是串行 `transact`。SF 在路径上的额外工作是 8.01 / 11.58 / 1.85 / 0.07 ms。单笔：

- `3356896` tx 131，工作 1.7 µs，`exec=6`（full 2，ordered 3）。tx 96，`exec=6`，ordered 5，full 0。链长 17，几乎每跳都重放，makespan 从 31 µs 变成 1.97 ms。
- `15274915` tx 1030，工作约 1 µs，`exec=7`（full 2，ordered 4），同时假边 12.9 ms。Resolve 和一条非 DAG 门叠在同一笔上。
- `19469097` 路径尾 tx 322，`exec=3`（full 1，ordered 1），门 27 ms 是继承的，重执行是自己的。
- 两块 C 上 FullReplay 笔和 OCC abort 笔的交是 71 和 63，只 SF 有的还有 37 和 43。OCC 也会重执行真冲突；SF 在交集之外又多了一段，而且对没有 FullReplay 的空转（335、429）另付 makespan。

Resolve 的界：值变了，重放一次，然后提交。不要对同一笔再叠一条活过提交的 OrderedReplay 门。不要对 lazy 余额差 FullReplay。不要在前驱已提交之后继续 Blocking。Partial rebind 在这四块上几乎不发生（值真的变了）；设计不要再把「再试一次 rebind」当成主路径。

## 5. 不做什么

- 不恢复 `Scheduler::next_task*` / `next_task_with_wave_ready` / `validate_occ_stage`。
- 不用 OCC pick 掩盖空转。这四块上 `occ_schedule_picks=0` 保持为正确性条件。
- 不把 OrderedReplay 收成只看 `is_executing`。那次测量让 `19469097` 的洞和 pick 变大。
- 不跳过 lazy 高读者重校验。`3356896` 上那是 `seq!=par`。
- 不把 `gas<4e6` 的顺序回退赢面算进这版。`3356896` gas 是 4.03e6，`n=176=THIN_SHELL_N`，它在脊上，LB 差是真的。
- 不追宽度。宽已经大于核数。
- 不落地本文件。下一轮若改代码，完成线是：这四块上路径头的 `first_start` 靠近 0 而不是靠近块尾反链的结束，tx 335 / 429 的 `n_exec` 落到个位数且不再定 makespan，关键路径 `exec>1` 的笔数下降，并且 `seq=par`、Soft=0、`occ_picks=0`。
