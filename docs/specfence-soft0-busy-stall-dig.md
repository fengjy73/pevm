# Soft=0：忙工作与有序停顿各占多少墙

**日期：** 2026-09-25（北京时间）
**基线：** `bb2361f`（PR #57 尖，`cursor/soft0-global-ideal-ready-pool-d2ad`）。产品调度、Avoid、Admit、Learn 未改。
**二进制：** `target/release/examples/specfence_3356896_compare` sha256 `d8cf7352d58deb833ac77444b716f9a20a79efa520285674145372b719b7b080`。`cargo +stable`（rustc 1.98.1），release，`profile.release.lto=false`。
**探针：** `SPECFENCE_BUSY_STALL=1` 才记。默认关。关旗不在新位点打 `Instant`。原始 JSON 与日志在 `results/soft0-busy-stall-dig/`。脚本 `scripts/specfence_busy_stall_report.py`。复用中位是丢掉冷轮后的 `sorted[len//2]`（偶数取上中位），不是两个中位的平均。

## 结论

大块仍要收到 SF/OCC ≥ 1.5 的那一截，不在有序脊 Handoff、有序提交、refuse/defer 或 WaitOnce 上。产品样的探针轮这些核停顿是 **0**。`refuse_ns` / `ordered_ns` / `gate_stall_ns` 是同一条策略计数的别名，关旗中位轮它是 **4.300 ms**，同时探针 handoff 是 **0**。

同机、关旗、协议复用中位：SF **7.539** / OCC **5.428** / 差 **2.111 ms** / ratio **0.720** / `ge_1_5=false`。锁定带仍是 SF 7.0–7.2、OCC 5.3–5.9，QuietExit 锚 SF 7.065 / OCC 5.306 / SF−Ideal 5.875。本页数字是这次宿主的测量，不另立墙。

这 2.111 ms 里，协议墙中位那一对的首次执行线程差是 **+6.146 ms**（SF 25.751，OCC 19.605）。四核饱和时墙上界约 **1.54 ms**。拆开是 post **+2.989**、interp **+1.818**、pre **+1.339** 线程。类是壳税，不是 RAW/WAR/WAW，也不是长链。重执行在这条里，不另加。

OCC 停在约 5.4 ms，是因为四核从大约 1.25 ms 起就被更短的同一次 EVM 打满，Ideal \(L_\mathrm{crit}\)=1.19 早已过去。OCC − \(L_\mathrm{crit}\) = **4.24 ms**。这是 SF−Ideal 的主体，两边共享，SpecFence 单独拿不走。Ideal Σwork=3.02 是另一只时钟，不能从本探针的 execute 里减掉再叫可回收墙。

## 协议与两只时钟

Soft=0 Instant-off。`est=0`，`soft=0`，`occ_picks=0`，`spine_cores_max≤1`。请求 8 个 worker，`taskset -c 0-3`，宿主 4 核（Intel Xeon，KVM）。worker 是线程，不是钉死的核。块 15274915（N=5，冷轮丢掉）和 3356896（N=3）。产品默认开着 `SPECFENCE_GLOBAL_IDEAL_READY_POOL` 和 `SPECFENCE_IDEAL_TIMED_ADMIT`，本测量不关。

Ideal 下界是 \(\max(L_\mathrm{crit}, \Sigma\mathrm{work}/C)\)，不用 \(n/C\)。15274915 锁定 \(L_\mathrm{crit}\)=1.19 ms，Σwork=3.02 ms，所以 Ideal = 1.19 ms。

**关旗的 `phase_*` 是产品 EVM 时钟。** 探针开时每次保留读都打 `Instant`，SF 比 OCC 胀得更多。探针大块复用中位墙是 **12.685**，其中两轮 handoff 线程 10.2 / 14.7 ms；四次关旗复用墙是 6.310–8.396，`yield_deadlock=0`，没有这截。探针墙不入锁定带。产品 EVM 用关旗 PHASE。停顿形状用最接近关旗的探针轮（SF iter4，墙 7.720，handoff 线程 0）。

线程纳秒除以 4 是饱和时的墙上界。`Instant` 含线程被抢占的时间，所以 `busy/4` 可以大于墙。8 个线程里没被分桶盖住的大约 8–11 ms 线程，两边都有，是抢占加上计时器外面的代码，不是 SF 专有桶。

`seq≡par`：探针开的大块和两块薄块都打印 `seq=par ok`。关旗大块 N=5 在打完墙之后打印 `seq!=par block=15274915`。这是关旗对照，不是探针开的那次。同库冷路径上 `seq!=par` 会抖；这次不把探针写成把确定性做坏。

## 4. OCC 为什么大约 5.3–5.9 ms 就结束

关旗 OCC 复用墙 5.078、5.107、5.428、5.586，协议中位 **5.428**，落在锁定带 5.3–5.9 里。exec 线程协议中位 **20.174**。四核打满时 20 ms 线程大约是 5 ms 墙，加上约 1.2 ms 的例子外壳，就是测到的 5.4。

OCC 与 SF 走同一个 `vm.execute` → `run_pevm_tx`。OCC 更快是因为同一次调用更短，不是因为少做了一遍块。中位对（OCC iter3 / SF iter4）：

| 桶 | OCC 线程 | SF 线程 | SF−OCC 线程 | /4 墙上界 |
| --- | ---: | ---: | ---: | ---: |
| exec = pre+interp+post | 19.605 | 25.751 | **+6.146** | **+1.54** |
| 其中 post | 8.515 | 11.504 | +2.989 | +0.75 |
| 其中 interp | 5.942 | 7.760 | +1.818 | +0.45 |
| 其中 pre | 5.148 | 6.487 | +1.339 | +0.33 |
| finish | 0.361 | 1.098 | +0.737 | +0.18 |
| val | 3.750 | 5.019 | +1.269 | +0.32 |
| pick | 6.383 | 1.026 | −5.357 | OCC 更大，且含 yield |
| 探针 lock（OCC iter4 / SF iter4） | 1.579 | 0.164 | SF 更小 | 不是 SF 超额 |
| 探针 noready | 0.456 | 0 | OCC 的队空 | 尾上几十微秒 |
| 探针 handoff | 0 | 0 | 0 | 产品样两边都没有 |

OCC 的验证、pick、状态锁获取都比 SF 贵或至少不便宜，仍然更早结束，因为 execute 超额大于这些。OCC 探针 iter4 的尾是 `stall_noready` 0.04–0.07 ms，在最后一笔 EVM（tx1138，0.463 ms，t0=4.038）之后。没有有序等待。

关旗 iter3 是反例里最干净的一笔：SF exec 线程 **19.861**，几乎等于 OCC 的 19.605，墙 **6.310**，只比 OCC 中位高 0.88 ms，而 span 却是四次里最长的 **2.805**。exec 线程回到 OCC 的量级时，墙跟着下来；span 变长时墙可以更短。

## 薄块 3356896

不替换任何薄块带。只确认没有另一只「有序停顿」墙。

defer=27 是计数。探针复用没有把这些 defer 记成核停顿。

## 判决

最大的 SF 专有、并且落在饱和尾上的桶，是首次执行比 OCC 多出来的大约 **1.5 ms** 墙（post 与 interp 为主），类是壳税。有序脊停顿和 FullReplay 都装不下剩下的大约 3 ms。剩下的距离是 OCC 已经站着的那层执行地板（本机 5.43，Ideal 1.19）。

下一刀不该再砍有序 Handoff、refuse/defer，或 Admit 的 Ideal 时钟。先前 Ideal 窗内远程 steal 已经是 0。要碰到 ≥1.5，得把共享的执行路径（post/MV，以及已经量过上界约 0.4–0.9 ms 的 interp/Detect）便宜到大约 3.6 ms 以下，也就是要快过 OCC，而不是只抹平 SF−OCC。脊外热 ℓ 上少做重执行仍然真实，本机墙上界 ≤0.8 ms。本页不改产品。
