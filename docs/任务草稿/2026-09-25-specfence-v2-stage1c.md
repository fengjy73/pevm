# SpecFence v2 stage 1c

## 目标

在 Stage 1b 的基础上，解释 C>1 的反伸缩，并按实测根因改调度，使 SF C=4 墙钟不超过 OCC C=4，且快于 SF C=1。PR 基线是 `cursor/specfence-v2-stage1b-ac6e`。

## 约束

- 上游 `vm.rs`、`mv_memory.rs`、`scheduler.rs`、`pevm.rs` 字节级不变。
- 不替换 opcode，保留 `static_gas()`。
- SEQ = OCC = SF = 链上头，块 15274915 与 3356896。
- 计时跑关掉计时器。归因先于改规则。新鲜运行、无预热。
- FullReplay：15274915 ≤ 12，3356896 ≤ 5。两种类键都报。
- 正确性覆盖 RAW、WAR、WAW 和写者链。参数保持自适应。

## 完成标准

- C=4 与 C=8、两块、两种类键的时间线：执行、按原因停车、提交滞后、验证、空转、簿记。
- 用同一次运行的 DAG 对比理想列表调度，按段解释 SF 墙钟减 Ideal_C。
- 用数字确认或否定 (a) 提交前缀等待、(b) 类头屏障、(c) 只在提交头验证、(d) 多工人簿记。
- 终局性沿读依赖传播，不等提交前缀。提前异步验证。类头屏障仅在本块冲突证据之后打开。
- 门：SF C=4 ≤ OCC C=4，且 SF C=4 < SF C=1。文档 Stage 1c 含归因、论证、前后表。

## 步骤

1. **已完成** — 时间线（`SPECFENCE_TIMELINE=1`，内部墙钟不含校准和 dump）。主机是 4 vCPU、Xeon family 6 model 207、L3 320 MiB。15274915 `(to, selector)` C=4：77 个收款人写者，执行合计 0.60 ms，链跨度 4.18 ms，墙钟 7.09 ms。76 跳全部在前一写者 **提交之后** 才开始；写者提交滞后合计 3.49 ms，占跳间空隙 3.59 ms 的 97%。C=8 同一条链跨度升到 7.30 ms（提交滞后 6.56 ms）。3356896 的 `dff71d59` 链同样 16/16 跳等提交。类头停车只有约 6 ms 的交易等待，其中约一半没有真边。`(code_hash)` 把空代码打成一个大类，admission 在类 6 上有 1064 次停车。验证 CPU 只有 0.34 ms，但提交滞后 p50 是 2.36 ms。簿记线程时间（publish 1.92、record 1.75、pre 1.34、coord 0.73 ms）在执行里，不是链跨度的主体。结论：(a)(c) 成立，是反伸缩的主因；(b) 类头本身不是墙钟，同类 admission/预测在 `code_hash` 上是额外串行；(d) 是线程时间，修完唤醒后才是下一截。
2. **进行中** — 依赖闭合终局性、提前验证、有证据才开类头和同类预测、提交不再挡住唤醒。
3. **待做** — 级联单测、等价测试、`scripts/soft0_percore_scan.sh` 新鲜扫描。
4. **待做** — `docs/specfence-v2-stage1.md` 增加 Stage 1c，并开 PR。
