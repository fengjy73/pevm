# OCC 更快完成同一 EVM 功

**日期：** 2026-09-24（北京时间）
**起点：** `401d014`（PR #53 tip，QuietExit + FirstExecCut + dig 探针）
**性质：** 设计/纸。允许只读相位探针。不落地产品刀。

## 目标

解释 Soft=0 Instant-off 上，同一块（主 15274915）OCC 墙比 SpecFence 短约 1.3–1.9 ms，而首次 Opt 里约 90% 是两边都要付的解释器+写提交。归因必须落到可测的调度壳、发布/验证节拍、执行次数或 SF 专有路径，不能只靠推测。

## 约束

- Instant-off。无 soft 重放叙事。无 Estimate、park-all、#47、HPC 加核。
- 不再把读元数据跳过、`first_start`-only、QuietExit 重拧当作答案。
- 不宣称 ≥1.5。不发明无探针墙。锁定带仍是 SF 7.0–7.2 / OCC 5.3–5.9。
- 探针只计数和计时，不改 pick / 验证 / 发布决策。

## 完成标准

- 同一二进制上 SF 与 OCC 的执行次数、解释器/提交/finish/验证/pick 线程时间有数。
- 协议绿：`seq≡par`，SF `occ_picks=0`。N≥3，`taskset -c 0-3`，请求 8 核。
- 笔记 `docs/specfence-soft0-occ-faster-same-evm-dig.md` 给出正向归因和一把设计-only 下一刀，或诚实结论：Soft=0 Instant-off 不能靠现有壳把这块类打到 ≥1.5。

## 步骤

1. **进行中：** 只读相位探针。`vm.execute` 拆成解释器前 / `run_pevm_tx` / 写提交；`finish_execution`、验证、pick 另计。OCC 的 pick 含 Block-STM 里等到有任务为止的 yield；SF 的 pick 只含 `schedule::pick`，空转仍在 `idle_ns`。
2. **待做：** release、LTO off、N≥3，大块为主，薄块可选。2 核冷检 `seq=par`。
3. **待做：** 把线程时间差对到 1.3–1.9 ms 墙，写笔记。产品行为除探针外不变。
