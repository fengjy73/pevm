# 经验记录

## 2026-09-23 — AccessEvent 三原语落地后 Soft=0 TPS 仍低于 1.5

**问题：** 统一访问学习 v1 + v1.1 落地后，焦点块 SpecFence 相对 OCC 的 TPS 比没有到 1.5。

**表现：** release、LTO off、N=5、请求 8 核（宿主 4 核）、Soft=0 Instant-off、reuse median。`estimate_block_sf=0`，`soft_wait_arms=0`，SpecFence `occ_picks=0`，`seq≡par`。3356896 ratio **0.671**（SF 116903.6 / OCC 174278.6，墙时 1.506 / 1.010 ms）。15274915 ratio **0.719**（SF 151063.5 / OCC 210072.6，墙时 8.116 / 5.836 ms）。薄块 reuse 的 `yield_ok` 是 0–1，`raw` 是 0–1，FullReplay 0–2。大块 reuse 的 `yield_ok` 约 7，`raw` 7–33，FullReplay 2–6，`yield_deadlock` 曾到 24。WAW/WAR 计数很高（大块 waw≈139，war≈2850），链长仍是 17 与 77，起点到终点占掉 SF 墙时的大部分。

**逻辑盲点：** 把 RAW/WAW/WAR 分类记进 IntraRecord，并在宿主读里对“已经能看见的未发布写者”自旋，并不等于关键链变短或反链填满核。第一波没有写集时读者看不到 Estimate，WaitTrueVersion 大多不触发；写者链仍按序占满 makespan。RetainHistory 的 pin 没有接到多版本丢历史的路径。现有 SF 调度税加在反链上，OCC 即使 abort 更多（薄块约 14，大块约 70–120）仍然更快。

**解决方案：** 保持 AccessEvent 三原语脊。下一刀砍长链：武装 ℓ 的剩余触及者在帧内等真 publish（目标是 reuse 的 `full_from_0` 归零），非触及者不要付 SF 调度税，用反链填核。不要加第四原语，不要用 Estimate 或 `next_task*` 门控 Avoid，不要把 Cross Prior 做成硬 Fence。本次数字来自 `specfence_3356896_compare` 的 `TPS_SUMMARY`，不是外推。
