# Soft=0：首次 Opt 跳过冷读之后，墙为什么没掉

**日期：** 2026-09-24（北京时间）
**代码：** 无探针墙是 `a253d6f`。本页的内部分解来自同一分支上的只读计时探针（每次首次 Opt 的 `basic` / `storage` 多一对 `Instant`）。
**块：** 15274915 为主。3356896 只作对照。
**协议：** Soft=0 Instant-off，release，LTO off，N=5，请求 8 核，宿主 4 核，`taskset -c 0-3`。复用中位是四次复用墙的 `sorted[2]`。`est=0`，`soft=0`，`occ_picks=0`，`spine_cores_max=1`。2 核冷检两块 `seq=par ok`。QuietExit 没改。

## 结论

冷读跳过已经打在复用轮上，而且几乎打在每一次首次 Opt 的读上。它不是墙。

无探针的大块复用中位仍是 **(A)**：SF **7.210 ms**，dig 是 **7.065 ms**。span 2.089 → 3.312，join-out 3.046 → 2.166，未开工 490 → 212。工作从脊尾之后挪到脊尾之前，总墙不动。

探针把一次首次 Opt 拆开之后，复用中位里大约 **90%** 的线程时间不在 Detect、不在跳过分支、不在 MV 读、也不在 `finish_execution`。它在 `basic` / `storage` 之外，也就是解释器和写提交。OCC 同样要做这段。跳过的那一截线程时间只有 **0.18 ms**。

## 无探针的脊尾之后

数字来自 `a253d6f` 的 N=5，中位行是 iter 1，链 **116/1219**。span 在尾的 `first_start`（3.927 ms）结束，最后一名工人在 6.011 ms 离开。这段墙是 **2.085 ms**。下面的毫秒是各线程之和，除以 2.085 得到「相当于几个线程」。8 个工人挤在 4 个核上，线程数可以加起来超过 4。

| 类别 | 线程 ms | 相当于几个线程 |
| --- | ---: | ---: |
| execute | 7.725 | 3.71 |
| validate / resolve | 1.828 | 0.88 |
| heal | 2.274 | 1.09 |
| yield | 0.129 | 0.06 |
| park | 3.822 | 1.83 |
| steal miss | 0.017 | 0.01 |

执行是这段里最大的一块，也盖满了 4 个核的大部分。验证不是这段墙。最后一次验证到最后离开仍是 0.073 ms，QuietExit 没有变长。

dig 的同一段是执行 14.054 ms / 2.982 ms ≈ 4.7 个线程，park 是 0，墙 7.065 ms。这次中位有 1.8 个线程的 park，墙仍是 7.210。**park 不是墙。** dig 在 park 为 0 时墙已经是 7.065。

这段上的执行次数是 224，约 **34 µs** 一次。dig 是 516 次、约 27 µs。单次没有变便宜；变少的是脊尾之后才开工的笔数。

## 探针：首次 Opt 里面是什么

探针复用中位的绝对墙不能和 7.065 比。这一轮 SF 12.408 / OCC 9.476，两边一起变慢，`Instant` 打在每次读上。下面只看这一轮内部的比例。中位行是 iter 2，`first_cut` 尝试 1145 次，链头 116，未开工 406。

| 桶 | 线程 ms | 占首次 Opt |
| --- | ---: | ---: |
| 保留的 Detect（spine peek + WaitOnce consult） | 1.100 | 2.3% |
| 跳过分支 | 0.183 | 0.4% |
| 其后的 MV / 账户 / 存储读 | 1.515 | 3.1% |
| 解释器 `code_by_hash` | 0 | 0 |
| `finish_execution` | 1.995 | 4.1% |
| 其余（解释器与写提交） | 43.705 | 90.1% |
| 合计 `vm.execute` + finish | 48.497 | 100% |

保留 Detect 的读是 **45** 次，跳过的读是 **2901** 次。跳过率约 **98%**。`code_by_hash` 为 0，是因为字节码在 `basic` 里用 `storage.code_by_hash` 取走，已经算进那 3.1% 的 MV，不是另一大块。

另外四次复用里，跳过分支都是 0.16–0.20 ms，保留 Detect 从 0.13 ms 到 2.61 ms，其余都在 87–93%。冷启动不是这个形态：iter 0 的 Detect 有 74.8 ms、511 次保留读，那是第一遍 WaitOnce，复用轮没有留下来。

非首次 Opt（链上的 hop、再执行、Blocking 重试）在中位行是 6.068 ms / 86 次，约 71 µs。次数比链长 77 多出一截，不是半块重放。无探针的 span 3.312 ms / 77 跳 ≈ 43 µs，和脊尾之后那 34 µs 的执行是同一档，链跳并没有贵一个数量级。

薄块复用中位（3356896，iter 3，SF 2.548，同样被探针抬高）：Detect 0.1%，跳过分支 0.4%，MV 2.4%，finish 5.3%，其余 91.8%。保留读 3 次，跳过 346 次。和厚块是同一个形状。另有一轮 heal 到 117 ms，不进这个比例。

## 对四个问题

1. **脊尾之后的墙，主体是执行。** 无探针中位上执行约 3.7 个线程，验证不到 1 个，yield 可以忽略。执行内部，复用轮上没被跳过的 Detect 是首次 Opt 的 0.3–4.8%，WaitOnce 就在这截里面（consult 和 peek 一起计）。跳过分支约 0.4%。验证是另一段线程时间，不是这 90%。

2. **跳过改了开工，没有减少执行量。** 无探针：未开工 490 → 212，span 2.089 → 3.312，join-out 3.046 → 2.166，墙 7.065 → 7.210。探针里首次 Opt 仍是大约 40 µs 量级，和 dig 的 27 µs、无探针脊尾之后的 34 µs 同一档，不是跳过之后变成几微秒。

3. **墙不是 Ideal 反链没做完的那一截。** Ideal 笔记里 `L_crit` 1.19 ms、`Σwork` 3.02 ms、`Σwork/4` 0.76 ms。同机 OCC 墙已经是 5.3–5.9 ms（探针轮甚至 9.5 ms）。首次 Opt 的线程时间是几十毫秒，不是 3 ms。4 个核在脊尾之后被执行盖住，缺的不是「宽度上还有空核」，而是每一笔解释器本身就这么长。

4. **下一刀只设计，不落地。** 不要再砍读路径元数据，也不要提前 `first_start`，也不要改 QuietExit。读侧跳过已经在复用轮上覆盖约 98% 的读，线程时间 0.2 ms，摊到 4 核大约 0.05 ms 墙，对不上 1.3–1.8 ms 的 OCC 差。还没被这次探针包住、而且数量级次之的 SF 专有段，是 AdmitIndep 的 `finish_execution`（中位约 2.0 ms 线程，约 4%）。下一刀若做，就只缩短这一段写发布，保持 `spine_cores_max≤1`，不加 Estimate，不 park-all。预期上界大约半毫秒墙，小于 OCC 差，也不碰到 1.5。若写路径探针显示它同样只有几个百分点，Soft=0 的元数据刀就停：剩下的墙是解释器，OCC 也要付。
